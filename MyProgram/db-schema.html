Схема базы данных

SQLite-база (travel_expert.db), которую создаёт и наполняет класс Database в main.py: семь справочников с вариантами ответов мастера вопросов, таблица направлений (база знаний) и журнал истории подборов.

Как это устроено

  • 7 справочников (budgets, continents, rest_types, seasons, durations, visas, interests) - фиксированные варианты ответов мастера вопросов. У каждого: code (уникальный текстовый код, используется для связи), name (что видит пользователь) и icon (эмодзи). У budgets дополнительно диапазон цены (min_price/max_price).
  • destinations - собственно база знаний (213 направлений на момент сборки): каждая строка - это правило вида «при таком сочетании критериев предложить эту страну/город». Можно редактировать прямо в приложении (окно «База знаний»).
  • history - журнал всех прошлых подборов: какие ответы дал пользователь, каким движком (use_ai) и что было рекомендовано.
  • seed_meta - служебная таблица из одной строки, хранящая версию набора направлений (destinations_seed_version); не связана с остальными таблицами - нужна только чтобы при обновлении приложения дозаполнить новые направления, не трогая уже существующие или добавленные пользователем вручную.
⚠️ Важный нюанс: связи на диаграмме - логические, а не настоящие FOREIGN KEY в SQL. Так сделано намеренно: у destinations и history многие поля (сезон, продолжительность, виза, интересы) умеют принимать специальное значение 'any' ("любой/не важно"), которое не соответствует ни одной строке справочника - настоящий внешний ключ такого бы не позволил. Соответствие кодов реальным справочникам проверяется на уровне логики приложения (RecommendationEngine / AISimulatedEngine в main.py), а не СУБД.
